Allowing contributors to use AI as a tool (like autocomplete, drafting helpers, or refactoring assistance) while requiring them to own, understand, and review the final code submission is becoming a modern standard for open-source projects. It keeps contributions flowing while ensuring quality and holding the developer accountable for what lands in the codebase.

To accommodate this cleanly, you can add an AI Assistance Policy directly into your CONTRIBUTING.md alongside your DCO guidelines.

Here is how you can frame that policy so it strikes the right balance between modern developer efficiency and rigorous code ownership:

AI Assistance Guidelines for Contributors

    AI Usage Policy:
We welcome the use of AI coding assistants (such as Copilot, ChatGPT, Claude, etc.) as productivity tools to help write, refactor, or debug code for the Krypton ecosystem. However, by submitting a pull request, you certify that:

    1.         You are the author of the contribution in terms of responsibility and understanding. You fully understand how the code works and can maintain it.
    2.         The code is compliant with the project's Apache 2.0 license and does not introduce proprietary, copyrighted, or plagiarized code snippets that violate open-source terms.
    3.         You have thoroughly reviewed and tested the AI-generated output for bugs, security vulnerabilities, or performance issues.

    Submitting raw, unreviewed, or bulk AI-generated code without personal verification or understanding is subject to rejection.
