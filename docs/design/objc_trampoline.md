# Objective-K → Objective-C Trampoline Bridge (Phase 3)

**Status:** Design only — nothing in this document is implemented yet. This
does **not** replace AppKit, Foundation, libobjc, or the existing
`okClass`/`okMethod`/`okRegister`/`okNew` manual bridge. This document adds
*automatic* synthesis of the same pattern from `objk protocol` / `objk object`
declarations.

Planning baseline: macOS arm64 Krypton 2.4.9 (released). The K-owned runtime
already supports witness tables with slot-based dispatch (`okKSlotSend*`);
this document picks up from there.

## Problem

The shortest reliable path to drive AppKit delegate-style behavior from
KryptScript today is:

```krypton
let sourceClass = okClass("KryptonTableLabSource")
okmMethod(sourceClass, "numberOfRowsInTableView:", funcptr(tableRows), "q@:@")
okmMethod(sourceClass, "tableView:objectValueForTableColumn:row:", funcptr(tableCell), "@@:@@q")
okmRegister(sourceClass)
let source = okNew(sourceClass)
okDataSource(table, source)
```

It works, and every shipped AppKit-table example uses exactly this shape. It
is also where most bugs live: encoding string typos, selector mismatches, and
trampoline signatures falling out of sync with the C ABI the second somebody
adds an `NSTableViewDataSource`-style argument.

Phase 3 eliminates that pattern for a *declared* subset of `objk protocol`
conformances. The shape it targets:

```krypton
objk protocol TableSource {
    objcSelector "numberOfRowsInTableView:" require numberOfRows() -> int
    objcSelector "tableView:objectValueForTableColumn:row:" require cell(column:text, row:int) -> text
}

objk object TableModel conforms TableSource {
    method numberOfRows() -> int = numberOfRowsInTableView
    method cell(column:text, row:int) -> text = cellForTable
}

just run {
    // ... construct the table ...
    let source = objkBridgeNew(TableModel, __objkRuntime)     // synthesizes + registers ObjC class
    okDataSource(table, source)
    msg(source, "release")
}
```

The `objcSelector` tag tells the frontend that this requirement must be
exposed to the Objective-C runtime as an instance method with a named SEL and
a fixed type encoding. That single declaration then drives:

- the witness table it belongs to,
- the ObjC class-pair allocation,
- the IMP trampoline family (one per arity),
- the selector/encoding binding,
- and the AppKit handoff point.

## What lives where

This phase deliberately splits across two layers:

**K-owned runtime** (`stdlib/objk_runtime_macos.k` — core, platform-neutral)

- Owns class/protocol/conformance/witness-table records; unchanged.
- Gains one new record family: **encoding pairs** for selector-tagged
  requirements. (See "Witness table extension" below.)
- Gains one new runtime verb: `objkBridgeRegister(class, protocol)` — seal
  ObjC protocol records and ObjC-class-pair allocation for every
  `objcSelector` requirement on that protocol.

**Native adapter** (`stdlib/choc_macos.k`, via `k:okui` or direct import —
macOS-specific)

- Owns `objc_allocateClassPair` / `objc_registerClassPair` /
  `class_addMethod` / the IMP family / `objc_getAssociatedObject` etc.
- Exposes `okBridgeClass(name, parent)` and `okBridgeRegisterMethod(class,
  selector, imp, encoding)` — exactly the existing `chocClassNew` /
  `chocClassAddMethod` family, renamed as the ObjC-visible path so the
  compiler can call them and diagnostics mention the binding target.

No layer is asked to be a general-purpose Objective-C runtime reimplementation.
If ObjC is missing or unhappy, the bridge fails closed and AppKit keeps the
old path.

## Protocol syntax (front end)

A protocol requirement may carry the `objcSelector` tag once per requirement:

```krypton
objk protocol TableSource {
    objcSelector "numberOfRowsInTableView:"              require numberOfRows() -> int
    objcSelector "tableView:objectValueForTableColumn:row:" require cell(column:text, row:int) -> text
}
objk protocol CloseListener {
    objcSelector "windowShouldClose:"                   require shouldClose(window:any) -> int
}
```

Constraints on `objcSelector`:

- A protocol may mix ObjC-ABI and K-native requirements freely; all K-native
  requirements work as before; only `objcSelector`-tagged methods are
  exported to the ObjC runtime.
- Duplicate selector names in one protocol (or across a parent chain) are a
  hard compile error.
- Arity is 0..2 user arguments, matching K-owned. This covers the common
  AppKit delegate cases (`numberOfRowsInTableView:`, `tableView:cell:…`,
  `windowShouldClose:`, `textDidEndEditing:`, …).
- Selectors are strings; they are matched byte-exactly against AppKit at
  runtime. No name resolution, no implicit prefix.

Front-end emitted fuel (sketch, generated by `compiler/compile.k` alongside
`irObjKSetup`):

1. Fingerprint every ObjC-tagged protocol requirement as a
   `__encodings.<protocol>.<selector>|<encoding>` record (see "Witness
   table extension").
2. For every class whose `conforms` list includes a selector-tagged protocol,
   emit a final registration call:
   ```
   LOAD __objkRuntime
   LOAD <ClassDecl>
   LOAD <ProtocolDecl>
   CALL okKBridgeRegister 3
   POP
   ```
3. The bridge call reads the encoding records, synthesizes the ObjC
   class-pair, and wires the trampolines. The bridge does **not** allocate
   the native object or give it to AppKit — the user calls `okBridgeNew(...)`
   (or `okDataSource(...)`-style helpers) to obtain it.

## Witness table extension

Existing table record (`kind 10`) is slot-indexed by requirement position.
Encoding strings need an independent channel so ObjC code paths can derive
the same slot without re-walking the protocol:

```text
requirement record (kind 8) — extends current layout
  Allocated size grows from 64 bytes today to 96 bytes:
  [0]=kind 8, [8]=next requirement, [16]=name, [24]=arity,
  [32]=slot (1-based, assigned at registration),
  [40]=firstClass, [48]=secondClass, [56]=resultClass,
  [64]=flags (bit 1 = objc-tagged, bit 2 = encoding-based trampoline),
  [72]=selector text (0 or arena handle), [80]=encoding text (0 or arena handle),
  [88] reserved for the dispatch-p1 tag / future use.

protocol record (kind 7) — extends current layout
  [0]=kind 7, [8]=parent, [16]=name, [24]=requirements list, [32]=registered,
  [40]=flags (bit 1 = contains objc-tagged requirements).

bridge record (kind 12) — per (class, protocol)
  [0]=kind 12, [8]=class, [16]=protocol, [24]=objc class pointer (native),
  [32]=slot table pointer (arena text records, mapping SEL→slot).
```

Association keys are created at runtime and retained by ObjC code (via
`objc_setAssociatedObject`); the bridge check leaves them alone.

## Universal trampoline dispatcher

One IMP per (class, protocol, slot, arity) — synthesizable via the existing
`funcptr` path. The front end does *not* synthesize a fresh IMP per class.
Instead, each trampoline is a unique name referring to one of a small set of
hand-written C-level helpers registered once per process:

```
callBridge0_int  (runtime, self, SEL cmd)          -> NSInteger
callBridge0_text (runtime, self, SEL cmd)          -> id
callBridge1_int  (runtime, self, SEL cmd, id arg1) -> NSInteger
callBridge1_text (runtime, self, SEL cmd, id arg1) -> id
callBridge2_int  (runtime, self, SEL cmd, id arg1, id arg2) -> NSInteger
callBridge2_text (runtime, self, SEL cmd, id arg1, id arg2) -> id
```

Each trampoline:

1. Reads its `self` (= the native bridge instance).
2. Resolves the K-owned object via `objc_getAssociatedObject(self, kKBridgeKey)`:
   the bridge instance carries `(runtime, kinstance, kprotocol)` in an
   associated `(NSMutableDictionary *)`, keyed with `kBridgeOwnerKey`.
   The preferred channel for the K instance is Krypton's arena handle stored
   under one fixed key; a second slot tracks the runtime pointer; a third the
   protocol handle's kind.
3. Resolves the slot by `_cmd` via `sel_getName(_cmd)` + a hash map built at
   class-registration time. (Or faster: store the slot index in a second
   associated object. `kBridgeFastPathSlot` on the proxy; set at registration.)
4. Pulls positional arguments (`id`) and converts them per the bridge's
   stored argument-shell (e.g. text → `okKTextValue(runtime, nsPtr)` — that's
   already exactly the round-trip pattern in `table_filter.ks`). Integer
   positions move through as native integers.
5. Calls `okKSlotSend*(runtime, kinstance, kprotocol, slot, ...)`.
6. Converts the return into an ObjC return value:
   - `int` → `NSInteger` (existing `callPtr` return slot)
   - `text` → borrowed `NSString *` — caller must retain per a documented
     resolver (`okBridgeUnretainedReturn` default, or class-specific calling
     convention tag on the protocol).

No ObjC exceptions cross the boundary. Any segfault inside a trampoline is
`EXC_BAD_ACCESS`/`NSInvalidArgumentException` — both are unrecoverable at the
ObjC level, and apps that want a diagnostic should hook `okLogBridge`.
Avoids exceptions on AppKit's main thread.

## Encodings are derived, not written

Given a Krypton requirement annotation `: text` and an `int` second argument:

- `text` → `@`
- `int` → `q`
- `any` → `@` (callers disambiguate; the trampoline hands an `id`)

Image encoding strings therefore follow the same derivation as `setup() → text`

```
"i@:@q"
```

(or its extension into edge cases where `q` does not suffice — structs are
**not supported**, passing by value is rejected at compile time.)

`any` as an argument position is an `id` at ObjC: matches the runtime's
untagged pointer. `do` / `doKRelease` return types use void `v`.

The encoding string is attached to the requirement at compile time; nothing is
parsed out of it later. Validation runs *before* `class_registerClassPair`:

- Register all IMPs first (via `class_addMethod`); registration prints the
  class name if any `class_addMethod` returns `0`.
- `objc_registerClassPair` is last.
- If a selector already exists on the synthesized class (subclassing
  NSObject, paranoia), the class registration is *not* performed and the
  `objkBridgeRegister` call returns a diagnostic code to the caller.

## Associated-object discipline

At new-instance time (`objkBridgeNew(...)` / `objcBridgeNew(...)`):

1. `[klass alloc]`;
2. `objc_setAssociatedObject(instance, kKBridgeOwnerKey, block(kclass),
   RETAIN)` — the bridge owns the ObjC side and blocks accidental reuse;
3. `objc_setAssociatedObject(instance, kKBridgeProtocolKey, block(kproto),
   RETAIN)`;
4. `objc_setAssociatedObject(instance, kKBridgeInstanceKey, block(kinstance),
   RETAIN)` — kinstance is an arena handle; the bridge retains the arena
   object for the lifetime of the ObjC proxy (and releases in
   `dealloc`/`okBridgeDealloc`).
5. `objc_setAssociatedObject(instance, kKBridgeSlotsKey, block(slots),
   RETAIN)` — slot-index table keyed by SEL.

All block keys are static `char*` constants (`"kBridgeOwner"`, etc.) — not
ARC-bridging gymnastics, because owners across `autorelease pool drain` are
accounted for deterministically:

- `dealloc` of the ObjC proxy invokes a `RELEASE` selector which calls
  `doKRelease(kinstance)` if the K object was retained at step 4.
- `objc_registerClassPair` happens *after* all IMPs are added.
- Bridge classes are never registered during an AppKit event.

## Concrete example: table filter with the bridge

```krypton
objk protocol TableSource {
    objcSelector "numberOfRowsInTableView:"              require numberOfRows() -> int
    objcSelector "tableView:objectValueForTableColumn:row:" require cell(column:text, row:int) -> text
}

objk object TableModel conforms TableSource {
    method numberOfRows() -> int = numberOfRowsInTableView
    method cell(column:text, row:int) -> text = tableCell
}

just run {
    // ...
    let model = objkBridgeNew(TableModel, __objkRuntime)
    okDataSource(table, model)
    okReload(table)
}
```

Generated artifacts:

- `TableModel` K-owned class (unchanged from current code path);
- `TableModel_TableSource_` ObjC class with two IMPs (`numberOfRowsInTableView:`
  → `trampoline_int0`, `tableView:objectValueForTableColumn:row:` →
  `trampoline_text2_id_id_q`) — or our unified dispatcher family;
- `__objk_encodings.TableModel.TableSource|numberOfRowsInTableView:@_NSInteger|q@:@\n…`
- `objkBridgeNew` that:
  1. allocates a K-owned object for `TableModel`,
  2. finds bridge record for `(TableModel, TableSource)` — created by
     `okKBridgeRegister` at class-registration time,
  3. allocates the ObjC proxy via `chocClassNew`-style APIs with the parent
     class `NSObject` (overrideable per-protocol with `objcParent "…"`),
  4. inserts the associated objects,
  5. returns the native ObjC instance; hand it straight to `okDataSource`.

## What the bridge refuses to do

- No struct-by-value passing (`NSRect`/`CGRect` by value through a Krypton
  trampoline). Those go through `msgRectFrame` / `msg_frame`-style special
  helpers in `k:objc`/`k:choc_macos`; `objcSelector` encodings with non-`@`
  / non-`q` arguments error at compile time.
- No varargs selectors.
- No protocol with mixed shells where one requirement returns an ObjC type
  that Krypton has no representation for.
- No dynamic class creation when K-owned construction would have been ABI
  legal but unsupported (e.g. `int64_t` > 2^63 — once `q` encodes anything
  else, the bridge errors out with `unsupported return encoding` rather than
  silently truncating).
- No ObjC++ constructors, no existing-class subclassing of AppKit classes.

## Relationship to the AppKit adapter

`okDataSource(table, source)` already accepts a native handle; the bridge
simply makes `source` a class that AppKit accepts as `NSTableViewDataSource`
without `okMethod`/`okClass` boilerplate. The bridge is the one chunk of
runtime ownership code it is permitted — and required — for the adapter to
retain, and `okDataSource(table, 0)` still detaches cleanly.

## Open implementation choices

These are deliberately left for the implementer (i.e. you) unless asked
otherwise:

- **Synthesis owner**: compiler (`obk` IR emission during registration
  of `TableModel`) vs. library (`okKBridgeRegister`). Current pattern uses
  the library path — it lines up with `doKConform`/`doKRegister` and has the
  runtime's existing locking/nesting. Do not second-guess without a plan.
- **ObjC pool discipline**: create a per-call `okAutoreleasePool` around
  `objkBridgeNew`; drain at the end of the runtime scope. We cannot let a
  stale proxy live longer than the K object it mirrors without a strong
  retain cycle.
- **Cross-platform**: no-op on Windows (K-owned runtime doesn't exist there);
  no-op or clear diagnostic on Linux. Do not try to emulate ObjC semantics.
- **Matching selector case**: exact match. No normalization pass.
- **NSString bridging**: `nsString()` is already used for `okSetText` etc.
  - it is `autoreleased` and ownership is the caller's responsibility —
  the bridge does **not** retain NSString returns into K-owned arena text
 ; it hands them to AppKit with the conventional borrow semantics of an
  AppKit data source (`objectValueForTableColumn:row:` callsites `retain`
  what they need themselves). `okDataSource(table, 0)` still cleanly detaches.

## What this does not commit to

- It does not commit to eliminating `okClass`/`okMethod`/`okNew`/`okRegister`
  dead code; they stay permanently as the manual escape hatch.
- It does not commit to a general Objective-C runtime replacement — the scope
  is precisely "make selector-tagged K-owned protocols act like ObjC
  delegate protocols for one class at a time."
- It does not commit to optional/nullable protocol requirements or
  implementation of NSInvocation — the trampoline knows every selector.
- It does not commit to `__bridge` or toll-free-bridging support.
